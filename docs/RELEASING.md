# Releasing termio

termio ships as a notarized `.dmg` hosted on **Cloudflare R2** behind
`downloads.termio.sh`, and updates itself in place with **Sparkle**. The source
repo stays private; only the build artifacts are public. Cutting a release is
one command — push a version tag — once the one-time setup below is done.

```sh
git tag v0.1.0
git push origin v0.1.0
```

That fires `.github/workflows/release.yml`, which builds + Developer-ID-signs the
app, notarizes it, packages a DMG, signs the Sparkle appcast, uploads both to R2,
and records a GitHub Release for the changelog.

## How versioning works

- **The git tag is the version.** `v0.1.0` → `CFBundleShortVersionString = 0.1.0`.
  To ship a new version, push a higher tag — nothing in the repo needs editing.
- **The build number is the commit count** (`git rev-list --count HEAD`), stamped
  into `CFBundleVersion`. It only ever increases, which is what Sparkle compares
  to decide an update is newer. Don't squash history in a way that lowers it.

## How updates reach users

- The app's `SUFeedURL` (in `packaging/Info.plist`) is
  `https://downloads.termio.sh/appcast.xml`. The workflow overwrites that object
  on every release, so each release automatically becomes the update everyone
  sees. The website Download button points at `https://downloads.termio.sh/termio.dmg`.
- R2 layout: the immutable per-release DMG at `v<version>/termio.dmg` (what the
  appcast links to), a stable `termio.dmg` copy (the website), and `appcast.xml`.
- Every release's `appcast.xml` is regenerated by **merging** the previous one
  (pulled from R2 first), so the update history and per-version notes survive.
- Sparkle verifies each download's EdDSA signature against `SUPublicEDKey` in
  `Info.plist`. That public key pairs with the `SPARKLE_ED_KEY` secret — termio
  reuses the same developer signing key as oakreader (Sparkle's docs: "you only
  need one signing key, no matter how many apps").

## One-time setup: Cloudflare R2 + DNS

1. Create an R2 bucket named **`termio-downloads`** (matches `R2_BUCKET` in the
   workflow).
2. Connect a **custom domain** `downloads.termio.sh` to the bucket (R2 → bucket →
   Settings → Custom Domains). This is what serves the public URLs and puts the
   files behind Cloudflare's CDN.
3. Create an **R2 API token** (Account → R2 → Manage API Tokens, Object Read &
   Write) — note its Access Key ID, Secret Access Key, and the S3 endpoint
   `https://<accountid>.r2.cloudflarestorage.com`.

## One-time setup: GitHub secrets

Set these with the `gh` CLI from the repo root (`gh auth login` first). Team ID
is `<TEAM_ID>` (your Apple Developer team).

### Cloudflare R2 (artifact hosting)

```sh
gh secret set R2_ACCESS_KEY_ID        # R2 token Access Key ID
gh secret set R2_SECRET_ACCESS_KEY    # R2 token Secret Access Key
gh secret set R2_ENDPOINT             # https://<accountid>.r2.cloudflarestorage.com
```

Optional (purges the edge cache so updates appear instantly instead of after the
~CDN TTL — without these the release still works):

```sh
gh secret set CLOUDFLARE_API_TOKEN    # token with Zone → Cache Purge
gh secret set CLOUDFLARE_ZONE_ID      # the termio.sh zone ID
```

### Developer ID signing certificate

Export your **Developer ID Application** certificate *and its private key* from
Keychain Access (select both rows → right-click → Export → `.p12`, set a
password), then:

```sh
base64 -i DeveloperID.p12 | gh secret set DEVELOPER_ID_CERT_P12
gh secret set DEVELOPER_ID_CERT_PASSWORD   # paste the .p12 password
```

### Notarization (App Store Connect API key)

Create an API key at <https://appstoreconnect.apple.com/access/integrations/api>
(role: Developer). Download the `.p8` once.

```sh
base64 -i AuthKey_XXXXXXXXXX.p8 | gh secret set ASC_API_KEY
gh secret set ASC_KEY_ID        # the 10-char Key ID
gh secret set ASC_ISSUER_ID     # the Issuer ID (UUID) shown on the keys page
```

### Sparkle signing key

The same EdDSA private key already used for oakreader. `scripts/setup-release.sh`
exports it from your keychain, verifies it matches the embedded public key, and
sets the secret:

```sh
./scripts/setup-release.sh
```

Or by hand:

```sh
curl -sL https://github.com/sparkle-project/Sparkle/releases/download/2.9.3/Sparkle-2.9.3.tar.xz \
  | tar xJ bin/generate_keys
./bin/generate_keys -p   # must print the SUPublicEDKey in packaging/Info.plist:
                         # zm3UpFrDf8tFcctK2vkEhrms6oFTp50AUb824lP9BAw=
./bin/generate_keys -x sparkle_private_key.pem
gh secret set SPARKLE_ED_KEY < sparkle_private_key.pem
rm sparkle_private_key.pem
```

## Local builds

`./scripts/build-app.sh` produces an ad-hoc-signed `termio.app` for local use
(Sparkle is embedded but auto-update is disabled in debug builds). To reproduce
a release-style signed bundle locally:

```sh
SIGN_IDENTITY="Developer ID Application" \
TERMIO_VERSION=0.1.0 TERMIO_BUILD=$(git rev-list --count HEAD) \
  ./scripts/build-app.sh
```

## Checklist for a release

1. Land all changes on `main`.
2. Pick the next version, e.g. `0.1.0`.
3. `git tag v0.1.0 && git push origin v0.1.0`.
4. Watch the **Release** workflow in the Actions tab.
5. When it's green, `downloads.termio.sh/termio.dmg` serves the new build and
   existing installs pick up the update on their next Sparkle check.
