# Agent Abstraction & Configuration

> Make every agent — shipped or user-added — a single config file, with one loader, one icon model, and one public hook contract, so adding an agent never touches Swift and never touches iOS.

> **As built (2026-07-18, Cut 1 landed):** `scripts/termio` now exposes
> `termio agent report <working|attention|done|idle>`. It reads `TERMIO_SESSION` and
> `PWD`, owns JSON escaping and the channel-scoped status socket, and has private
> `--transcript` / `--reply` modes for Claude's stdin transcript and Cursor's required
> `{}` stdout reply. Every shipped installer (`JSONHookFile`, `TOMLHookBlock`, and all
> `PluginFile` variants) calls that contract instead of embedding `printf | nc`.
> Installers stamp the running app bundle's absolute `termio` / `termio-dev` path, with
> the channel-specific `/usr/local/bin` path only as the bare-build fallback, so dev and
> release hooks cannot cross sockets through `PATH`. Reinstall strips both the new
> `agent report` marker and legacy `agent-status.sock` entries. Grok still installs its
> dedicated `~/.grok/hooks/termio.json` file. Termio-owned plugin files likewise use
> the concise `termio.js` / `termio.ts` names; installers remove recognized legacy
> `termio-status.*` files during upgrades so agents never load duplicate hooks. The
> sandbox schema field was already removed by the completed sandbox-removal work, so §6
> required no code change.

> **As built (2026-07-18, Cut 2 landed):** macOS now has one closed `AgentIcon`
> primitive model (`image(URL)`, `vector`, `symbol`, or `terminalGlyph`), and Shared
> carries the wire-ready, data-shaped `IconRef` (`asset`, inline `png`, `vector`, or
> `symbol`). Both `BrandImageAsset` enums and their agent-specific resource switches
> are gone; resource names and file paths resolve through the same generic image
> renderers. iOS already renders `IconRef`, with `AgentKind` retained only as a temporary
> compatibility adapter until Cut 5 moves the catalog onto the wire and deletes it.

> **As built (2026-07-18, Cut 3 landed):** the eleven shipped definitions now live
> under `Resources/agents/*.json` and resolve through the same `AgentManifest` DTO as
> legacy user manifests. The static `builtins` array and hardcoded hook factories are
> gone: manifests select the closed resume strategy, icon primitive, JSON/TOML/plugin
> dialect, destination, transcript capture, and event→state data. Plugin contents remain
> shipped templates generated by Termio; manifests cannot supply executable code. User
> definitions already override bundled ids as full replacements, while id-only session
> persistence is unchanged. Bundled filenames carry numeric prefixes solely to preserve
> the existing picker order under unordered resource enumeration; ids and wire tokens do
> not include those prefixes. Existing assets moved under `Resources/assets/` so SwiftPM
> can process that directory generically while copying `Resources/agents/` intact.

> **As built (2026-07-18, Cut 4 landed):** user manifests load from the channel-scoped
> flat directory `~/.termio[-dev]/config/agents/*.json`, with full user-over-bundled
> replacement by `id`. On first load, each legacy `agents/<folder>/agent.json` is copied
> to `<id>.json`; an in-folder relative icon becomes the collision-resistant sibling
> `<id>.<ext>` and the copied JSON path is rewritten. The destination manifest is
> published atomically only after its icon, no existing destination is overwritten,
> and source files are removed only after the flat copy is complete. A collision or
> migration failure is logged and the remaining legacy manifest is still loaded, so a
> failed migration cannot hide an agent. Absolute/tilde icon paths remain untouched.

> **As built (2026-07-18, Cut 5 landed):** `RosterAgent` now carries optional
> `tintHex` and `IconRef` fields, preserving decode compatibility with an older Mac and
> wire compatibility with an older iOS client. The Mac resolves that portable metadata
> beside each runtime `AgentIcon`: bundled assets remain resource-name references,
> vector marks and SF Symbols remain primitive references, and user image paths are
> rasterized once at catalog load into inline PNG data. iOS builds its session and launch
> menus from the roster catalog, with a small Claude/Codex/Terminal fallback only while
> paired to an older Mac. `AgentKind` and every agent-specific iOS mapping are deleted;
> unknown or disabled session ids degrade to a generic terminal glyph without changing
> the persisted `Session.agent` id or the roster session wire shape.

## Where this sits

[`20260707-agent-extensibility.md`](./20260707-agent-extensibility.md) (RFC, as-built through Cut 1–2)
already turned `AgentPreset` into `AgentDefinition`, added user agents under
`~/.termio/agents/<id>/agent.json`, and made JSON-hook-file status **config-driven**.
This doc is the **next phase** that RFC defers (its §7 Cut 3 and §8 open questions):

1. **Built-ins become config too** — collapse the two worlds (hardcoded built-ins vs.
   on-disk user agents) into one manifest path.
2. **Kill the icon enums** — the concrete sprawl that made adding Grok touch six files.
3. **A public hook contract** (`termio agent report`) — answers the RFC's open question
   §8.4 ("a documented `$TERMIO_SOCK`/`$TERMIO_SESSION` contract?") and de-duplicates the
   per-dialect `printf | nc` baked into every installer.
4. **iOS is driven by the Mac** — delete the parallel `AgentKind` enum; user agents render
   on the phone for free.
5. **Drop `sandboxStandDown`** from the schema (see
   [`20260718-sandbox-removal-and-restoration.md`](./20260718-sandbox-removal-and-restoration.md)).

Non-goals from the RFC still hold verbatim: no plugin platform, no embedded Lua/JS runtime,
**Termio never executes agent-provided code** (hooks always run in the agent's process),
and the wire format stays `{termio_session, state, cwd}` over a Unix socket.

## Motivation: the sprawl is now measured

Adding the Grok agent (2026-07-18) touched **six files** with parallel `switch`
statements, for one agent:

- `Sources/termio/AgentDefinition.swift` — the definition + `builtins` array
- `Sources/termio/Models.swift` — `BrandImageAsset` case + `resourceName` + `fileExtension`
- `Shared/Sources/TermioShared/BrandIcons.swift` — `AgentKind` case + `BrandImageAsset` case
  + `tintColor` + `brandImage` + `AgentIconView` render + `resourceName`
- `ios/Sources/Models.swift` — `init(wire:)` + `menuIcon` render
- `Sources/termio/HookListener.swift` — the hook factory (only if it has hooks)
- two `grok-favicon.png` copies

Two root causes, neither of which is "we need a plugin system":

1. **Icons are compile-time enums, triple-declared** (`BrandImageAsset` on macOS,
   `BrandImageAsset` + `AgentKind` in Shared, `AgentKind` in iOS), each with a `switch` per
   property. User agents already dodge all of this — their icon is just
   `AgentIcon.imageFile(URL)`. Built-ins pay the enum tax for no benefit.
2. **There are two agent models.** macOS uses `AgentDefinition`; iOS/shared re-derive
   everything from a separate `AgentKind` enum keyed on the wire string. Every agent is
   declared twice — once as a Swift struct, once as an enum case with its own switches.

This tax was already paid four times since the RFC shipped (Kimi, Antigravity, Hermes, Grok).

## Principles

- **Enumerate primitives, not agents.** The code should list *icon kinds*
  (image / vector / SF-symbol / terminal-glyph — a closed set of ~4 that never grows) and
  *behaviors* (resume strategies, hook dialects). It should never list agents (an open set
  that grows every release).
- **Config selects behaviors; it never expresses logic.** A manifest picks a named
  `resume`/`dialect`/icon kind that Termio implements. The only place a user can inject
  executable behavior is inside the agent's own process (a shell hook that calls the public
  contract) — never inside Termio.
- **One source of truth per fact.** The Mac owns the agent catalog; iOS renders what it's
  told. A pane's status has one authority (hooks win over screen-scrape, as today).
- **Small surface.** Load once at launch (no hot-reload runtime, no marketplace). Files are
  cheap; parallel `switch` statements are the tax we're removing.

## 1. Unified manifest

Built-ins and user agents flow through **one** decode path. Built-ins ship as bundled JSON
instead of static Swift.

### Layout

```
<app bundle>/Resources/agents/*.json      built-ins:  claude.json, codex.json, grok.json, …
~/.termio/config/agents/*.json            user agents + overrides   (~/.termio-dev in dev channel)
~/.termio/config/agents/<id>.png          optional sibling icon (or inline / a path in the json)
```

This flattens the current folder-per-agent (`~/.termio/agents/<id>/agent.json`) into
`config/agents/<id>.json`. Migrate existing folders on first load.

### Precedence

- Load bundled first, then user; **merge by `id`, user wins.** A user can drop `claude.json`
  to override a shipped agent's command/flags (e.g. launch through a wrapper), not just add
  new agents. This reverses the RFC's "built-in wins": brand-protection isn't worth blocking
  a legitimate override, and `id` collision is the user's explicit intent.
- A bad file logs and is skipped, never crashes the set (already the behavior).
- A session referencing a removed agent degrades to `AgentDefinition.fallback(id:)` (already
  the behavior).

### Schema

`claude.json` (a built-in expressed as data):

```json
{
  "id": "claudeCode",
  "name": "Claude Code",
  "wire": "claude",
  "command": "claude",
  "permissionBypassFlag": "--dangerously-skip-permissions",
  "resume": "claude",
  "icon": { "vector": "claude" },
  "install": "https://claude.com/claude-code",
  "hooks": {
    "type": "json",
    "file": "~/.claude/settings.json",
    "dialect": "claude",
    "capturesTranscript": true,
    "events": [
      { "on": "UserPromptSubmit", "state": "working" },
      { "on": "PreToolUse",  "state": "working", "matcher": "*" },
      { "on": "PostToolUse", "state": "working", "matcher": "*" },
      { "on": "PermissionRequest", "state": "attention", "matcher": "*" },
      { "on": "Stop", "state": "done" },
      { "on": "SubagentStop", "state": "working" }
    ]
  }
}
```

A user adding a brand-new agent — `myagent.json`:

```json
{
  "id": "myagent",
  "name": "My Agent",
  "command": "myagent --fancy",
  "icon": { "path": "myagent.png" },
  "status": { "working": ["thinking"], "attention": ["approve\\?"] }
}
```

Field summary:

| field | meaning | closed set? |
| --- | --- | --- |
| `id` | stable slug + persistence key | — |
| `name` | display name | — |
| `wire` | companion-wire token (defaults to `id`; only `claudeCode`→`claude` differs) | — |
| `command` | CLI binary + fixed args; omitted = plain shell | — |
| `permissionBypassFlag` | appended when the user enables bypass | — |
| `resume` | resume strategy | **yes** — `none`\|`claude`\|`codex`\|`opencode`\|`pi` |
| `icon` | see §3 | kind is closed |
| `install` | install page URL | — |
| `hooks` | see §4 | `type`/`dialect` closed |
| `status` | screen-scrape regex fallback | — |

`sandboxStandDown` is **removed** (see §6). `resumeStyle` becomes the string `resume`,
selecting the same behaviors that exist today (`ResumeStyle` enum, see
[`20260716-agent-resume-identity.md`](./20260716-agent-resume-identity.md)).

## 2. The loader

`AgentCatalog` already merges built-ins + user agents; the change is that built-ins become
bundled JSON, so there is one decode path and the static `builtins` array disappears:

```swift
final class AgentCatalog {
    static let shared = AgentCatalog()
    let all: [AgentDefinition]

    private init() {
        let bundled = Self.load(dir: Bundle.termioResources.appendingAgents())
        let user    = Self.load(dir: AppChannel.homeConfigDirectory / "config/agents")
        self.all = Self.merge(bundled, overriddenBy: user)   // user wins by id
    }

    private static func load(dir: URL?) -> [AgentManifest] { /* decode *.json, skip+log bad */ }
}
```

`AgentManifest` (Codable DTO) → `AgentDefinition` (runtime) via one `resolve()`, the same
DTO/runtime split that already exists between `UserAgentManifest` and `AgentDefinition`,
promoted to cover built-ins. `commandIndex`, `resolve(_:)`, `definition(for:)`, and the
foreground-process detection (herdr) are unchanged — they read from `all`.

## 3. Icon model

Replace the three enums with **one icon reference** carried in the manifest and resolved by
one loader. The rendering primitives (`BrandImageView` for images, `BrandLogoShape` for the
two vector marks, `HugeIconView` for the terminal glyph, SF Symbol for user agents) stay —
they are the closed primitive set.

```swift
enum AgentIcon {          // macOS + shared, one definition
    case image(URL)       // built-in favicons AND user PNG/SVG — resolved from a resource name or a path
    case vector(BrandLogo) // the 2 shipped vector marks (claude, codex)
    case symbol(String)   // SF Symbol (user agents)
    case terminalGlyph
}
```

Manifest `icon` is one of:

- `{ "vector": "claude" }` — a shipped vector mark (a 2-entry map that never grows; or
  rasterize claude/codex to PNGs and drop even this).
- `{ "asset": "grok-favicon" }` — a bundled image resolved by name.
- `{ "path": "myagent.png" }` — a user image (relative to `config/agents/`, or absolute/`~`).
- `{ "symbol": "sparkles", "tint": "#14B8A6" }` — SF Symbol + tint.

Deleting `BrandImageAsset` (macOS + shared) removes the `resourceName`/`fileExtension`/
`tintColor`/`brandImage` switches. Adding an agent then touches **zero** icon code.

## 4. The hook contract

The one thing a user genuinely *cannot* express as data today is the report mechanism:
Termio bakes `printf '{…}' | nc -U <socket>` into every installer, per dialect. Fix that by
publishing **one public contract** and letting the manifest declare only *where to call it*.

### The contract (new, public)

```
termio agent report <working|attention|done|idle>
```

A tiny `termio` subcommand that reads `$TERMIO_SESSION` and `$PWD`, optionally slurps stdin
for a `transcript_path`, and writes the report to the status socket
(`~/.termio/agent-status.sock`). This *is* the public hook API — the answer to RFC §8.4.
Users never touch `nc`/`printf`/socket paths again; those become an implementation detail
behind one documented command. `HookListener`'s socket layer is unchanged.

### Wiring — `hooks.type` selects how the call reaches the agent's lifecycle

| `type` | for agents that… | Termio does | covers |
| --- | --- | --- | --- |
| `json` | have a Claude/Cursor-shaped JSON hook file | injects `termio agent report <state>` into `file` per `events`, in `dialect` | Claude, Codex, Cursor, Grok |
| `toml` | use a TOML `[[hooks]]` block | appends a marked block calling the contract | Kimi |
| `plugin` | have a JS/TS plugin dir | drops a shipped plugin template into `dir` that calls the contract | OpenCode, Pi, Amp |
| *(omitted)* | have no hook system | falls back to `status` screen-scrape regex | long-tail user agents |

All four converge on `termio agent report`. The existing installers (`JSONHookFile`,
`TOMLHookBlock`, `PluginFile`) stay — they just write a CLI call instead of a raw socket
pipe, and read path/dialect/events from the manifest instead of hardcoded factories.
Install/uninstall/strip-by-marker are unchanged.

### The escape hatch

An agent with a bespoke hook system Termio doesn't model: the user makes *its* hook run
`termio agent report working`. Termio needs to know nothing — the contract is public. If
they also want Termio to install/remove that wiring, they declare `hooks.type: "json"` (or
`plugin`) and point at the file. Either way: **no Termio code change.**

### Authority

When both `hooks` and `status` are declared, `hooks` wins (already enforced:
`hookSpec != nil` ⇒ `statusRules = nil`). One authority per pane.

## 5. Data vs. code — the boundary

- **Data (the manifest):** command, flags, install URL, icon, event→state map, hook file
  path, status regex, wire name. Adding an agent = one file.
- **Code (closed, named sets the manifest selects from):** `resume` strategies,
  `hooks.dialect`, the icon primitive kinds, the report contract. A genuinely new hook-file
  shape or resume mechanism is a real (and rare) code change — correct.

This line is what keeps the system from becoming a plugin VM: **the manifest picks from
shipped behaviors and declares where to inject a call to a public contract; it never
expresses logic Termio must run.**

## 6. Sandbox field removal

`sandboxStandDownArguments` leaves the struct and the schema. With Termio no longer owning a
sandbox, there is nothing to stand an agent's own sandbox down for. See
[`20260718-sandbox-removal-and-restoration.md`](./20260718-sandbox-removal-and-restoration.md). The
"yolo-but-boxed" use case, if ever wanted back, returns as a **launch-prefix seam**
(user prepends their own wrapper via config), not as a first-class field.

## 7. iOS is driven by the Mac

Today iOS re-derives an agent's icon/name/tint from a hardcoded `AgentKind` enum
(`ios/Sources/Models.swift`) keyed on the wire string, so every agent is declared a second
time and user agents can't render on the phone at all. Fix: the Mac already sends an agent
catalog in every roster (`RosterAgent { id, name }`, `CompanionServer.companionRoster()`) —
enrich it, and iOS stops knowing what agents exist.

### Wire change (additive, backward-compatible)

```swift
public struct RosterAgent: Codable, Sendable, Equatable {
    public let id: String
    public let name: String
    public var tintHex: String?      // NEW — optional, old clients ignore
    public var icon: IconRef?        // NEW
}

public struct IconRef: Codable, Sendable, Equatable {
    public var vector: String?   // "claude" | "codex"
    public var asset: String?    // "grok-favicon"  (bundled PNG, by name — iOS has it locally)
    public var png: String?      // base64          (a user agent's own image)
    public var symbol: String?   // SF Symbol       (user agent, no image)
}
```

`RosterSession.agent` stays the `id` string — a key into the catalog the Mac sent. iOS
builds `[id: RosterAgent]` from the roster and looks sessions up in it.

### Each side

- **Mac** (`companionRoster()`): map `AgentDefinition.icon` → `IconRef` (one switch, where
  the definition already lives). Built-ins send `{ asset }` or `{ vector }`; user agents send
  `{ png }` (read + base64) or `{ symbol }`.
- **iOS:** delete `AgentKind` and `init(wire:)`. Replace `AgentIconView(agent:)` with
  `AgentIconView(ref: IconRef)` switching on the primitive (png → `BrandImageView`,
  vector → `BrandLogoShape`, symbol → SF Symbol, else terminal glyph). The call sites
  (`RosterStore.swift:99/201`, `Models.swift:155`) read name/tint/icon from the `RosterAgent`.

**Icon-shipping choice:** built-ins send an `asset` name (tiny payload; iOS loads the bundled
PNG it already has); user agents send `png` bytes. The duplicated thing we're killing is the
Swift enums, not two copies of a PNG file. (Alternative — always send bytes + cache by id —
is only worth it if we ever want iOS to bundle zero agent icons.)

Result: a user's `config/agents/foo.json` arrives on the phone as `{ name, png, tint }` and
renders with its real icon — no iOS update, ever.

## 8. Migration (incremental, build-green each step)

1. **`termio agent report` + repoint installers** to call it (behavior-identical; verify
   status dots still work). *Keystone — do first; it de-risks the rest and is independently
   valuable.*
2. **Icon model:** collapse the three enums into `AgentIcon`/`IconRef`, icon as
   resource-name/path. Removes ~10 of the 12 per-agent edit sites.
3. **Built-ins → bundled `Resources/agents/*.json`;** one decode path; delete the static
   `builtins` array.
4. **User dir → `config/agents/*.json`;** migrate existing `~/.termio/agents/<id>/`.
5. **iOS wire-catalog** (§7); delete `AgentKind`.

Each step is shippable alone. Persistence is untouched throughout — `Session.agent` is still
the `id` string (see RFC §4.5).

## 9. Open questions

1. **Vector marks:** keep the `vector` kind for Claude/Codex (crisper at 13px) or rasterize
   to PNGs and delete the last agent-specific icon code? Leaning keep.
2. **Overrides:** does user-wins-by-id fully replace the built-in, or shallow-merge fields
   (override just `command`, inherit the rest)? Shallow-merge is friendlier but adds a merge
   rule. Leaning full-replace for simplicity, revisit if painful.
3. **Hot-reload:** still launch-load only. File-watch is a nice-to-have, deferred (RFC §7 Cut 3).
4. **`termio agent report` discovery:** hooks call the `termio` on `PATH`; for the dev channel
   the CLI is `termio-dev`. The injected command must resolve to the right channel — stamp the
   absolute CLI path (or a `$TERMIO_CLI` env) at install time, mirroring how `TERMIO_SESSION`
   is stamped on the PTY.

## 10. What we still don't build

Reaffirming the RFC's rejected alternatives, plus this phase's:

- No plugin platform / marketplace / manifest-API.
- No embedded Lua/JS runtime; **Termio never runs agent code** (the escape hatch runs in the
  agent's process).
- No smart-receive (Termio running per-agent normalization scripts).
- No sandbox subsystem (§6).
- No hot-reload runtime.
