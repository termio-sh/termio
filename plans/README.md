Generated by `improve-animations` against commit **74889a8** (branch `main`).

`prefers-reduced-motion`, `UISpringTimingParameters`/`usingSpringWithDamping` =
springs). Each plan is self-contained — an executor needs only the plan file.

## Recommended execution order

1. **001** — highest leverage (the app's primary gesture), smallest surface, no
   dependencies. Do this first.
2. **002** — trivial two-line curve swap, no dependencies.
3. **003** — depends on **002** (both edit the attach-menu dismiss at
   `TerminalAccessoryBar.swift:469`; 003 assumes the curve is already
   `.curveEaseOut`). Run 002 first.
4. **004** — additive, larger, gesture-heavy, and reuses 001's velocity formula
   and spring — do it after 001 has landed and been felt. Highest risk; real
   device recommended for the feel check.
5. **005** — additive, independent of everything else; can land any time.

## Dependencies

- **003 → 002**: same line touched; 002 must land first.
- **004 → 001**: 004 reuses the normalized-velocity formula and spring identity
  established in 001; land and verify 001 first.
- 002, 005 are independent of the others.

## Corrective vs. additive

- **001–003** fix things that feel wrong today (dead-on-release drawer, sluggish
  ease-in exits, inconsistent Reduce Motion). Ship these.
- **004–005** add motion where there is none. Optional polish — take them if the
  delight budget is worth the extra surface area.

## Rejected during the audit (do not "fix")

- `AppDelegate.swift:140` — inside a string literal (demo/wire code), not live.
- `TerminalViewController.swift:495` — keyboard tracking correctly inherits the
  system's own animation curve from `userInfo`.

  and translated to grow out of the (+) key, deliberately mirroring UIMenu. Only
  its *easing* (002) and *Reduce-Motion gating* (003) were findings, not the scale.
